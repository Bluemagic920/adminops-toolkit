Microsoft Intune MDM Troubleshooting Guide

Diagnose Windows device enrollment failures, compliance issues, MDM event-log errors, and Microsoft Entra join problems with a repeatable, read-only-first workflow.

1. Start with these checks

Before changing enrollment or policy settings, capture the device's current state and the time the issue occurred.

  1. Confirm internet connectivity and accurate date, time, and time zone.
  2. Confirm the affected user has the appropriate Intune license and enrollment permissions.
  3. Check whether the device is already managed and whether an enrollment restriction or device limit applies.
  4. Determine whether the problem is enrollment, policy delivery, compliance evaluation, or access to a specific resource.
  5. Record any error code and the device name, Windows build, and relevant timestamps.
Start with observation and evidence collection. Avoid unenrolling devices or deleting registrations until you understand the impact on access, certificates, and management.

2. Troubleshoot Intune enrollment

On Windows 10/11, open Settings → Accounts → Access work or school. Check whether the expected work account and management connection are present. The exact labels vary by Windows version and enrollment method.

Common causes to investigate

  • Missing or incorrect Intune licensing or MDM user scope.
  • Enrollment restrictions, device enrollment limits, or unsupported enrollment scenarios.
  • Microsoft Entra join/registration problems or stale device records.
  • Proxy, TLS inspection, DNS, or firewall interference with Microsoft endpoints.
  • Conflicting or incomplete previous management enrollment.

Correlate the user-facing error with Windows MDM logs and the device's enrollment state in the Intune admin center. Don't assume a single error code has the same cause in every environment.

3. Find DeviceManagement-Enterprise-Diagnostics-Provider event logs

Open Event Viewer → Applications and Services Logs → Microsoft → Windows → DeviceManagement-Enterprise-Diagnostics-Provider → Admin. This log can help identify MDM enrollment, configuration, and policy processing problems.

The event channel is commonly referenced as Microsoft-Windows-DeviceManagement-Enterprise-Diagnostics-Provider/Admin.

Read recent MDM events with PowerShell

Get-WinEvent -LogName 'Microsoft-Windows-DeviceManagement-Enterprise-Diagnostics-Provider/Admin' -MaxEvents 40 |
  Select-Object TimeCreated, Id, LevelDisplayName, Message |
  Format-List

Compare timestamps to the attempted enrollment or policy sync. Review the event message and associated HRESULT or error code, not just the event ID.

The command above reads logs; it does not change enrollment or device policy. Log availability and permissions can vary by machine.

4. Collect diagnostics with MdmDiagnosticsTool.exe

MdmDiagnosticsTool.exe is a Windows diagnostic utility that collects MDM-related troubleshooting information. Use it when event logs alone don't explain the failure.

Example: collect a diagnostic package

mkdir C:\Temp\MDMDiagnostics
MdmDiagnosticsTool.exe -area DeviceEnrollment;DeviceProvisioning;Autopilot -cab C:\Temp\MDMDiagnostics\MDMDiagnostics.cab

Run the commands in an elevated Command Prompt. The supported areas and syntax can differ by Windows version; run MdmDiagnosticsTool.exe /? to confirm available options. If your shell interprets semicolons, use Command Prompt or quote the area list as appropriate.

Diagnostic packages may contain device identifiers, enrollment details, and other sensitive operational data. Store and share them only through approved support channels.

5. Check Microsoft Entra join with dsregcmd /status

Run the following in Command Prompt on the affected Windows device:

dsregcmd /status

Review AzureAdJoined, DomainJoined, WorkplaceJoined, and, when available, the user/device authentication status. Expected values depend on whether the device is Entra joined, hybrid joined, or registered.

For user-context fields such as AzureAdPrt, run the command in the affected user's session. An elevated command prompt under a different account may show different user-context information.

Do not automatically run dsregcmd /leave as a first troubleshooting step; leaving device registration can disrupt access and management.

6. Investigate compliance and policy sync

In the Intune admin center, open the device record and compare its last check-in, compliance state, assigned policies, and per-setting status. On the device, check the work or school account connection and available sync controls.

  • Confirm that the relevant compliance or configuration policy is assigned to the expected user or device group.
  • Check for conflicting settings, pending restarts, or requirements the device cannot satisfy.
  • Allow for policy processing and reporting delays; a successful sync does not guarantee immediate compliance.
  • Use event logs and the Intune policy status details to isolate the failing setting.

7. Check whether Microsoft Intune has a service issue

If multiple users or devices begin failing at the same time, check official service-health information before making large-scale configuration changes. Tenant-specific incidents may be visible in the Microsoft 365 admin center's Health → Service health section, subject to admin permissions.

For official documentation, see Microsoft Intune troubleshooting documentation and Windows MDM diagnostics guidance.

Search terms such as “Microsoft Intune issues today” can indicate a service concern, but they do not establish that an outage is occurring.

8. Frequently asked questions

Where is the DeviceManagement-Enterprise-Diagnostics-Provider/Admin log?

Event Viewer → Applications and Services Logs → Microsoft → Windows → DeviceManagement-Enterprise-Diagnostics-Provider → Admin.

What does MdmDiagnosticsTool.exe do?

It collects MDM troubleshooting information for analysis. It does not itself fix enrollment or compliance problems.

Why does dsregcmd /status show unexpected join values?

Possible explanations include an incomplete join, a different enrollment model, or running the command under a different user context. Compare the output with the device's intended identity state.

Should I unenroll and re-enroll a failing device?

Not as the first step. Collect logs, verify licensing and assignments, and understand the consequences before removing management or registration.
